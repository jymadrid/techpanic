# 指数日线双源选择验收

## 固定规则

- 每次在线运行均查询东方财富与新浪，离线模式不发请求。
- 有效历史末日期较新者优先；同日或东方财富较新时采用东方财富。
- 东方财富无效时采用有效新浪；新浪无效时采用有效东方财富。
- 两源均不可用才使用通过完整性检查的缓存。
- 不混合两源的价格历史，也不采用盘中当天行作为最终收盘价。
- legacy source_index 仅控制请求先后，不覆盖上述选择规则。

## 回归与运行结果

- 完整 Windows 测试：142 passed。新增 24 个源/流水线用例，涵盖同日优先、东方财富落后、新浪失败、双方无效、空表、坏价格、少量样本、未来日期、时区解码、缓存 TTL 不阻挡、来源 JSON 与离线零网络。
- ruff 检查 src/tests/scripts：通过。pip check：无依赖冲突。
- 真实双源查询于北京时间 2026-10-09 16:29 左右完成：东方财富两标的均 RemoteDisconnected；新浪科创50 1637 行、创业板指 3969 行，均截至 2026-10-08。按规则采用新浪，不宣称已取得 10 月 9 日数据。
- Windows 实际启动双源查询、计算和输出正常，退出码 2；明确提示未取得当日日线。QVIX 缓存仍截至 2026-09-30。
- 真实东方财富成功的网络路径在本机未验证通过；东方财富有效返回及日期比较路径通过模拟响应回归。不要将模拟成功写成实测访问成功。

## 输出与边界

日志显示两源末日期/失败原因与选择依据；JSON 新增 index_data、price_only.source 和 latest_data_date，兼容保留 latest_trading_day，但它只表示已取得数据截止日。

指数不再按 6 小时 TTL 跳过查询；QVIX 的 TTL 保持独立。收盘后仍无当天数据时会提示并保守降级。程序未验证官方交易日历，因此工作日长假也可能提示；QVIX 滞后数只相对已取得的价格日期计算。

PI 公式和权重不变。采用另一源的整段历史可能因覆盖范围/精度差异改变历史分位。数据、独立环境和运行验收产物不入仓，也不创建 Release。
