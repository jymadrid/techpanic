# 常见问题

## 读数与判读

### A 和 B 为什么不一样？哪个是对的？

**两个都对。** 它们是同一指标的两个口径：

| | A 完整口径 | B 即时口径 |
|---|---|---|
| 因子 | 加上期权的隐含波动率 | 只有价格 |
| 数据日 | QVIX 盘后发布，常滞后 1 个交易日 | 当日收盘 |

日常看盘用 B，因为它一定包含今天；做研究、写报告引用 A，因为它是完整定义。

### 那我能用 A 减 B 得到「今天的冲击」吗？

**不能。** A 与 B 的因子集合和数据日都不同，相减的结果里混着「口径差异」和「时间差异」，无法拆分成有意义的量。

正确做法：比较**同一口径**在两个时点的变化，例如「昨天 B = 58.2，今天 B = 61.5，所以即时口径抬升了 3.3」。

### PI 高就意味着恐慌吗？

**不是。** 必须结合方向：

- PI 高 + 方向向下 → **恐慌**
- PI 高 + 方向向上 → **狂热**（不是恐慌）
- PI 低 → 无论涨跌，市场平静

这就是为什么每条读数都附带方向，请两个一起看。

### PI 能预测明天的涨跌吗？

**不能。** PI 是一个**状态度量**（温度计），刻画当下市场的恐慌程度，不包含任何对未来方向的预测。

### 为什么历史分位和我记忆中的不一样？

分级锚点默认用**扩展窗口**（只用当日及之前的数据），这是为了消除前视偏差。代价是：当新数据到来时，早先某日的百分位可能发生极微小变化。

如果你需要**可复现、可对外引用**的固定阈值，请用 `level_anchor = "frozen"` 并写死 `[index.frozen_anchors]`，见 [CONFIGURATION.md](CONFIGURATION.md)。

### 「极度恐慌」出现了，我该抄底吗？

**本工具不回答这个问题，也不构成投资建议。** PI 只描述市场状态，不判断价格是否合理。请阅读 [DISCLAIMER.md](../DISCLAIMER.md)。

## 使用与安装

### 第一次运行为什么要好几分钟？

绝大部分时间花在下载 QVIX 宽表（914 KB）上。上游 `1.optbbs.com` 是第三方小站，服务端限速约 8 KB/s，实测同一个文件有时 1.7 秒、有时 123 秒。程序给了 150 秒单次超时和 300 秒总预算，超时立刻降级用缓存。

第二次运行会优先用缓存，很快。

### 需要注册账号或申请 API Key 吗？

**完全不需要。** 所有数据来自公开免费接口，无需登录、无需 Key、无需付费。

### 需要联网吗？

**首次必须联网。** 本仓库不附带任何数据。

如果只是想重算已有缓存，用 `--offline`，它会零 HTTP 请求地跑完。

### 支持 Python 3.9 吗？

不支持。**最低 3.12。** 原因有两个：

1. 依赖要求：本项目 pin 的 numpy 2.5.3 要求 Python ≥3.12，pandas 与 akshare 要求 ≥3.11；
2. 标准库要求：配置解析用 `tomllib`，它从 3.11 才有（3.10 需要额外装 tomli，本项目不想增加依赖）。

启动脚本会在建好虚拟环境后**主动校验版本**，不合要求会明确告诉你当前版本和该怎么做。

### 支持 Windows 7 吗？

未测试。依赖里的 `curl_cffi` 与 `mini-racer` 是预编译 wheel，较旧的 Windows 可能无法安装。建议 Windows 10 及以上。

### 会不会把我电脑搞乱？

不会。`start.*` 脚本创建的是项目内的 `.venv` 目录，不修改系统 Python，也不写注册表。删掉整个文件夹就彻底干净。

### 数据存在哪？

- 缓存：`data/cache/`
- 输出：`data/output/`
- 日志：**本项目不写日志文件**。诊断信息直接打在终端（每个数据源的失败原因都在里面），需要完整堆栈时加 `--debug`
- 溯源记录：`data/cache/_manifest.json`

全部在项目目录内，删掉 `data/` 即可重置。

### 怎么更新到最新版？

```
git pull
pip install -r requirements.txt
```

**不需要**删除 `data/`，缓存可以继续用。

## 数据

### 能拿到多少历史？

| 标的 | 起始 |
|---|---|
| 科创50 指数 | 2020 年 |
| 创业板指 | 2010 年 |
| QVIX（科创50 期权） | 2023 年 6 月 |
| QVIX（创业板指期权） | 2022 年 9 月 |

指数的历史比 QVIX 长，所以早期的「完整口径」不可用，程序会自动只给即时口径。

### 能加别的板块吗？（半导体、新能源、北证50……）

技术上可以，在 `config.toml` 的 `[targets.*]` 里配置。但有两个前提：

1. 该指数必须在数据源里有日线（新浪格式 `sh`/`sz` + 6 位代码）；
2. 该指数必须有对应的 QVIX 期权数据，否则只能出即时口径。

目前内置可用的 QVIX key 见 [CONFIGURATION.md](CONFIGURATION.md)。

### 数据准吗？

- 指数日线：来自新浪财经，与公开行情一致。
- QVIX：来自第三方小站，我们做了三道校验（列数断言、合理性断言、与缓存交叉校验），但**无法为上游数据质量背书**。

严肃研究前请自行与权威来源交叉验证。

### 为什么程序会「降级」？

降级不是错误，是**诚实的失败方式**。可能出现的情况：

| 提示 | 含义 | 处理 |
|---|---|---|
| QVIX 未发布，完整口径停在某日 | 上游还没更新，正常 | 无需处理，看 B |
| 使用本地缓存（滞后 N 个交易日） | 抓取失败，用了旧数据 | 稍后重跑，或检查网络 |
| 某标的无可用指数数据 | 该标的跳过 | 看是否能上网 |

所有降级都会在输出里显式标注，**绝不会静默发生**。

### 退出码 2 是失败吗？

**不是。** 它表示「部分降级」，最常见的原因是 QVIX 滞后 1 个交易日——这在 A 股是**正常状态**，因为期权数据盘后才发布。只有退出码 3（无数据）和 4（环境问题）才需要处理。

## 开发

### 测试怎么跑？

```
pip install -r requirements-dev.txt
pytest
ruff check src tests
```

### 测试会联网吗？

不会。所有测试用固定随机种子现场生成数据，不依赖仓库里的任何数据文件，也不访问网络。CI 里另有一次真实的端到端运行。

### 为什么测试里有「坏数据」的用例？

因为最难发现的故障不是「程序崩溃」，而是「**程序正常退出但数据是错的**」。那 3 个负例专门验证：坏数据会被拒绝、会降级、会被标注，而不会被静默接受。

### 我发现算法有问题，怎么反馈？

开 Issue，附上：

- 你认为错在哪里（附推导或反例）；
- 你用的数据和配置；
- 期望结果与实际结果。

方法学上的质疑非常欢迎——我们宁可被证伪，也不要错误的正确感。
